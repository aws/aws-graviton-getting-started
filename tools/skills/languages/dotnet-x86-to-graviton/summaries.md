* "summaries.md": "This file. Canonical index of every file in the skill and when to read each one. Linked from SKILL.md and POWER.md; useful when entering mid-skill or needing the full file map."

* "SKILL.md": "Main entry point (Agent Skills format). Contains scope guardrails, entry/exit criteria, transformation workflow overview with phase routing, test failure handling, and documentation output mapping. Read this first."

* "POWER.md": "Main entry point (Kiro format). Same content as SKILL.md with Kiro-specific frontmatter (displayName, keywords, author)."

* "phases/phase1-static-analysis.md": "Detailed steps for Phase 1: prerequisites (SDK, Python for the check program), project structure analysis (deployment type, solutions and projects including ones no solution lists, the starting point from evaluated project properties: modern .NET on Linux or Windows, or .NET Framework, target OS and libc with glibc version, Lambda runtime and page size), the dependency tree with the per-RID native check, native library validation (every committed native file and assembly judged by content, P/Invoke and NativeLibrary loads, executables run and binaries downloaded at run, build or deploy time, OS packages checked for arm64 on the target OS) with the tiered FAIL/WARN/PASS policy, dependency classification including transitives, AWS SDK IMDSv2 support and build-tool packages with OS/arch RIDs, architecture-specific code (architecture checks, x86 intrinsics, vector width, PlatformTarget and RuntimeIdentifier pins, Windows-only APIs through CA1416, Windows and .NET Framework descriptors), and the .NET version check with live support status and the framework change gate."

* "phases/phase2-resolution.md": "Detailed steps for Phase 2: native library resolution (aarch64 builds of committed native files, cross-compiled for plain C libraries, shipped next to the x64 build, architecture-aware loading), dependency updates for MUST UPGRADE items only (lowest version whose linux-arm64 native files load on the target, written through the project's own mechanism, target RIDs added and lock files regenerated, substitutions and target framework changes as user decisions), architecture detection code updates (Arm64 branches, IsSupported checks with portable paths, script gates), build configuration (PlatformTarget and RuntimeIdentifier pins, Dockerfile publish on $BUILDPLATFORM with -a $TARGETARCH, Native AOT, Lambda architecture and runtime, manifests), and documented Graviton runtime recommendations with evidence levels."

* "phases/phase3-validation.md": "Detailed steps for Phase 3: working container runtime detection, emulation limits on x86 hosts (bounded container runs, no compiling under QEMU, Microsoft's QEMU support statement, x86-64 executables that do not fail there), .NET SDK alignment and session-scoped SDK switching, build validation with a publish of every executable project per target RID and a content scan of each output, INFRA/ARM64/PRE-EXISTING failure classification with a misleading-symptom table, container validation including a scan of the files inside the image, tests on ARM64 from a native build, code coverage on arm64, startup checks (process architecture, native loads, IMDSv2, Lambda), and summary generation."

MUST be read before starting."
